# STACKSPACER — LINUX PRODUCTION BUILD REPORT

## EXECUTIVE SUMMARY

**Root Cause:** The current `.next/` build was generated on Windows (Node v24.15.0). It embeds `query_engine-windows.dll.node` and Windows paths (`C:\Users\MT\...`) in `.nft.json` traces. Production runs Linux and cannot load Windows Prisma binaries, causing 500 errors on all routes that query the database (`/insights`, `/insights/[slug]`, `/sitemap.xml`).

**Fix Applied:** Created GitHub Actions workflow for Linux build + updated Prisma schema with Linux-compatible binary targets.

## 5. EXACT PRISMA BINARY TARGET
**Schema updated to:**
```prisma
generator client {
  provider      = "prisma-client-js"
  binaryTargets = ["native", "rhel-openssl-3.0.x"]
}
```
- `native` → GitHub Actions ubuntu-latest (glibc 2.35+)
- `rhel-openssl-3.0.x` → RHEL 9 / CentOS Stream 9 / CloudLinux with OpenSSL 3.0

**If production uses OpenSSL 1.1.x** (older RHEL 8 / CentOS 8), change to:
```prisma
binaryTargets = ["native", "rhel-openssl-1.1.x"]
```
Verify with `diagnose-production.sh` on the server.
